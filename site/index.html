Why rust-psp

A complete SDK, not just bindings

A maintained fork of overdrivenpotato/rust-psp, updated for Edition 2024 on recent nightly Rust and extended well beyond the original crate.

  • Edition 2024, pinned nightly

    Built and tested in CI against a pinned nightly, with #[unsafe(no_mangle)]-style attributes and unsafe_op_in_unsafe_fn enforced across the workspace.

  • Raw access when you need it

    psp::sys exposes 830+ OS functions across 50+ system libraries (threads, I/O, GE, audio, networking, codecs), resolved by NID at load time, plus the sceGu/sceGum graphics library written in Rust.

  • Safe wrappers by default

    RAII handles for files, sockets, audio channels, fonts and threads. Allocators and VRAM return Result with structured errors instead of panicking.

  • Kernel mode

    module_kernel!() unlocks Media Engine control, hardware registers, syscall hooking, NAND, IR remote and exception handlers on custom firmware.

  • Experimental std

    A PSP platform layer for the standard library: String, Vec, std::fs, std::thread, std::sync and std::time on the device.

  • One command to a playable EBOOT

    cargo psp builds core/alloc (or std) for mipsel-sony-psp, converts the ELF to a PRX, and packs PARAM.SFO and assets into EBOOT.PBP.

Get started

From zero to EBOOT.PBP

You need a nightly Rust toolchain, this fork's cargo-psp tools, and a crate that depends on psp from Git.

This fork is not published on crates.io

The psp and cargo-psp crates on crates.io belong to the upstream project. Running cargo install cargo-psp or adding psp = "…" from crates.io gets you upstream, not this SDK. Install the tools and the library from GitHub as shown below.

  1. Pin a nightly toolchain

    The PSP target needs nightly features and -Z build-std, which requires the Rust source component. The SDK uses nightly internals, so pin the nightly CI tests against; the newest nightly may not build.

    rust-toolchain.toml
    [toolchain]
channel = "nightly-2026-04-13"
components = ["rust-src"]

  2. Install the build tools

    Installs cargo-psp plus the prxgen, pack-pbp, mksfo and prxmin helpers it calls. They must be on your PATH.

    Any platform
    cargo install --git https://github.com/AndrewAltimit/rust-psp cargo-psp --locked

    Builds the host tools from this repository and places all five binaries in ~/.cargo/bin.

    Linux
    # Download the *-linux-* assets from the latest release, then:
chmod +x cargo-psp-linux-* prxgen-linux-* pack-pbp-linux-* mksfo-linux-* prxmin-linux-*
for t in cargo-psp prxgen pack-pbp mksfo prxmin; do
  cp "$t"-linux-* ~/.cargo/bin/"$t"
done

    Linux binaries are attached to each GitHub release. On other platforms, use cargo install.

    Terminal
    git clone https://github.com/AndrewAltimit/rust-psp
cd rust-psp/cargo-psp
cargo build --release
# Add rust-psp/cargo-psp/target/release to your PATH

    cargo-psp is its own workspace because it runs on the host, not the PSP.

  3. Create a crate that depends on psp

    Use cargo new my-game, point the dependency at this repository, and replace main.rs. The entry point is psp_main, registered by psp::module!.

    Cargo.toml
    [package]
name = "my-game"
version = "0.1.0"
edition = "2024"

[dependencies]
psp = { git = "https://github.com/AndrewAltimit/rust-psp" }
# optional features: "kernel", "std", "embedded-graphics"
    src/main.rs
    #![no_std]
#![no_main]

psp::module!("my_game", 1, 0);

fn psp_main() {
    psp::callback::setup_exit_callback().unwrap();
    psp::dprintln!("Hello PSP from rust!");
}

  4. Build and run

    Run in the PPSSPP emulator, or copy the file to ms0:/PSP/GAME/my-game/EBOOT.PBP on a Memory Stick for real hardware.

    Terminal
    cargo psp --release
# Output: target/mipsel-sony-psp/release/EBOOT.PBP

    Optional: a Psp.toml next to Cargo.toml sets the XMB title, icon, background and other PARAM.SFO fields (for example title = "My Game").

High-level modules

    System registers: GPIO and USB enable, interrupts.

psp::sys

The raw layer: 830+ extern functions generated by the psp_extern! macro, each stub tagged with its NID so the PSP loader can resolve it, plus the GU/GUM graphics library implemented in Rust. Largest areas: networking, kernel threads and memory, PSMF, USB, utility dialogs, RTC and I/O.

Kernel mode

Full hardware access on custom firmware

Enable the kernel feature and declare your module with module_kernel!. It sets module attribute 0x1000 and starts psp_main on a kernel thread.

src/main.rs
#![no_std]
#![no_main]

psp::module_kernel!("MyKernelApp", 1, 0);

fn psp_main() {
    psp::callback::setup_exit_callback().unwrap();
    // Kernel-only: Media Engine clock
    let me_mhz = unsafe {
        psp::sys::scePowerGetMeClockFrequency()
    };
    psp::dprintln!("ME clock: {}MHz", me_mhz);
}

Unlocks

  • Media Engine boot and task execution (psp::me)
  • Memory-mapped register I/O (psp::hw), GPIO, Syscon and Sysreg
  • Syscall hooking for CFW plugins (psp::hook, sctrlHEN*)
  • NAND flash, SIRCS infrared and USB bus-driver syscalls
  • CPU exception handler registration

Requires custom firmware such as ARK-4 or PRO. In PPSSPP the module loads, but kernel-only calls may return errors.

Standard library experimental

Use std on the PSP

With the std feature, cargo psp overlays a PSP platform layer onto your rust-src and rebuilds the standard library with -Z build-std.

src/main.rs
#![feature(restricted_std)]
#![no_main]

psp::module!("std_hello", 1, 0);

fn psp_main() {
    psp::callback::setup_exit_callback().unwrap();
    let greeting = String::from("Hello from std!");
    let names = vec!["sajattack", "overdrivenpotato"];
    for name in names {
        psp::dprintln!("{greeting} Hi, {name}.");
    }
}

Use psp = { git = "…", features = ["std"] }. cargo psp detects the feature; RUST_PSP_BUILD_STD=1 forces a std build. Output goes to target/mipsel-sony-psp-std/.

The PSP overlay ships in the rust-psp repository, and cargo psp finds it next to your psp dependency, so it always matches the revision you build against. See docs/std.md.

Toolchain

What cargo psp does

A thin wrapper over cargo build that drives three small host tools. All of them, plus a standalone PRX minifier, are written in Rust.

Host tools
BinaryRole
cargo-pspCargo subcommand: builds, then runs the steps below for every binary target.
prxgenConverts the linked ELF into a PSP PRX module.
mksfoWrites PARAM.SFO (title, disc ID, version, region…) from Psp.toml.
pack-pbpPacks SFO, icons, background, music and the PRX into EBOOT.PBP.
prxminStandalone utility that minifies and strips PRX files.
